# Unit Test 생성

대상 클래스에 대한 단위 테스트를 JUnit5 + Mockito로 생성합니다.

## 사용법

```
/unit-test [클래스명]           # 지정된 클래스에 대한 단위 테스트 생성
/unit-test                     # 최근 수정된 파일 중 테스트가 없는 클래스 탐색 후 생성
```

## 규칙

- given-when-then 구조로 작성
- Repository, 외부 API 호출 등 모든 외부 의존성은 `@Mock` + `@InjectMocks`로 처리 (실제 DB·네트워크 접근 금지)
- 정상 케이스 + 예외 케이스(NotFound, 검증 실패, 권한 없음 등)를 최소 1개씩 포함
- 테스트 메서드명은 한글로: `메서드명_상황_예상결과()` 패턴 (예: `주문생성_재고없음_예외발생()`)
- 하나의 `@Test`는 하나의 시나리오만 검증 (여러 assert를 억지로 몰아넣지 않기)

## 프로세스

1. 대상 클래스(`[클래스명]`이 없으면 최근 git diff 기준 변경된 서비스 클래스)를 찾는다
2. public 메서드 목록과 각 메서드가 의존하는 대상(Repository, 외부 서비스 등)을 파악한다
3. `src/test/java` 하위, 대상과 동일한 패키지 경로에 테스트 클래스를 생성한다
   (이미 테스트 클래스가 있으면 새 파일을 만들지 않고 누락된 메서드의 테스트만 추가한다)
4. `./gradlew test --tests [생성한 테스트 클래스]`로 실행해서 통과 여부를 확인한다
5. 실패하면 원인을 분석해서 수정하고, 통과할 때까지 반복한다

## 완료 후 보고 형식

```
생성된 테스트: <파일 경로>
테스트 케이스: <N>개
- <메서드명_상황_예상결과>: <검증 내용 한 줄>
실행 결과: 통과 <N>/<N>
```

## 참고사항

- 테스트가 이미 존재하는 메서드는 건너뛰고, 커버되지 않은 메서드만 추가한다
- Mock 설정이 지나치게 복잡해지면(3개 이상의 의존성을 얽어서 mocking해야 하는 경우), 해당 메서드는 통합 테스트로 넘기는 게 낫다고 알려준다
